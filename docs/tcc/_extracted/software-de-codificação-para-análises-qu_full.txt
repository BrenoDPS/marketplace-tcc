RESUMO 
 
O presente trabalho aborda o desenvolvimento de uma plataforma voltada para 
facilitar a análise qualitativa de dados, com foco na etapa de codificação. O problema 
identificado é a limitação das ferramentas atuais, que são frequentemente caras ou 
complexas, o que restringe o acesso a pesquisadores com menos recursos ou 
familiaridade técnica. Nesse contexto, o objetivo principal é criar uma solução 
acessível que permita a codificação de dados textuais, organizando informações e 
auxiliando na extração de insights. A metodologia adotada foi baseada no ciclo de vida 
de desenvolvimento de software em modelo iterativo, que possibilitou ajustes 
contínuos durante o processo de criação. A implementação utilizou a linguagem 
Python e uma arquitetura de três camadas, garantindo flexibilidad e e escalabilidade 
ao sistema. O software foi avaliado por meio de um estudo de caso com usuários 
reais, envolvendo testes de usabilidade e questionários de satisfação. Os resultados 
mostraram que a ferramenta é capaz de cumprir com as funcionalidades básicas que 
se propõe, mas ainda carece de implementações  mais robustas, a fim de se tornar  
uma alternativa viável e acessível às soluções comerciais existentes. 
 
Palavras-chave: Análise qualitativa. Desenvolvimento de Software. Codificação 
de dados qualitativos.

ABSTRACT 
 
The present work addresses the development of a platform designed to facilitate 
qualitative data analysis, with a focus on coding techniques. The identified problem is 
the limitation of current tools, which are often expensive or complex, restricting access 
for researchers with fewer resources or limited technical expertise. In this context, the 
main objective is to create an accessible solution that allows the coding of textual data, 
organizing information and assisting in the extraction of insights. The m ethodology 
adopted was based on the software development life cycle in an iterative model, 
allowing for continuous adjustments throughout the creation process. The 
implementation was carried out using the Python language and a three -layer 
architecture, ens uring the system’s flexibility and scalability. The software was 
evaluated through a case study with real users, involving usability tests and satisfaction 
questionnaires. The results showed that the tool can fulfill its basic functionalities, but 
still re quires more robust implementations to become a viable and accessible 
alternative to existing commercial solutions. 
 
Keywords: Qualitative analysis. Software Development. Qualitative data coding.

1 INTRODUÇÃO 
No mundo moderno, observa-se um aumento exponencial no volume de dados, 
impulsionado pela proliferação da tecnologia digital e da conectividade global (Vianna, 
2021). Este influxo massivo de informações abrange uma ampla variedade de tipos, 
desde dados estruturados até não estruturados, tanto quantitativos quanto 
qualitativos. Tais dados demandam processos de gestão cuidadosos, que envolvem 
desde a coleta até a forma como são analisados e armazenados (Garg; Popli; Sarao, 
2021). 
Embora os dados quantitativos sejam frequentemente valorizados por sua 
objetividade e capacidade de análise estatística direta, os dados qualitativos 
desempenham um papel igualmente crucial, fornecendo insights ricos e nuances 
sobre aspectos subjetivos e contextuais da experiência humana. Desde análises de 
sentimentos em mídias sociais (Sforza; dos Santos, 2023) até pesquisas qualitativas 
em ciências sociais  (Goldenberg, 2003) , os dados qualitativos oferecem uma 
perspectiva valiosa que complementa e enriquece a compreensão dos fenômenos 
complexos que permeiam a sociedade. 
Em vista disso , desenvolveram -se diversas técnicas para analisar essas 
informações de caráter subjetivo,  como o processo de codificação para a análise 
semântica, associando códigos à trechos específicos  do conteúdo (Ho; Limpaecher, 
2022). Paralelamente, ferramentas que auxiliam nessa atividade foram desenvolvidas, 
os chamad os Computer-assisted qualitative data analysis software  (CAQDAS) 
possuem recursos que agilizam esse processo. Todavia, a maioria dos CAQDAS são 
caracterizadas por custos substanciais e uma estrutura de código fechado, como o 
MAXQDA, ATLAS.ti, NVivo e Delve, o que acarreta a limitação do acesso democrático 
a tais recursos no âmbito da pesquisa. 
Por outro lado, alternativas gratuitas de código aberto, como o projeto 
QualCoder (Curtain, 2023) , apresentam desafios próprios, como a escassez de 
documentação e uma organização do código menos sistemática.  Outro exemplo é o 
projeto Label Studio (Tkachenko et al., 2022), voltado para rotulação de dados para 
aprendizado de máquina, que oferece recursos específicos para essa técnica, mas 
não atende completamente às necessidades de pesquisa qualitativa.

2 PESQUISA E ANÁLISE EM DADOS QUALITATIVOS 
A pesquisa qualitativa , ou descritiva,  desempenha um papel importante na 
compreensão e exploração da complexidade dos fenômenos sociais, culturais e 
psicológicos (Allan; Skinner, 2020; Olsen, 2015; Rahman, 2016) . Nesse contexto, a 
análise de dados qualitativos , do inglês – Qualitative data analysis (QDA), emerge 
como uma abordagem para extrair insights significativos a partir de dados ricos e 
contextualizados. 
2.1 DADOS QUALITATIVOS X QUANTITATIVOS 
Para uma compreensão mais aprofundada do processo de QDA, é necessário 
entender e discernir entre os tipos de dados e os métodos de pesquisa associados a 
eles. Enquanto a pesquisa quantitativa busca quantificar e medir fenômenos por meio 
de números e estatísticas, a pesquisa descritiva se concentra na compreensão em 
profundidade dos significados, experiências e perspectivas dos participantes  
(Rahman, 2016). 
Dessa forma, a diferença entre os tipos de dados presentes em cada uma pode 
ser definida de acordo com a seguinte afirmação: 
Os dados quantitativos são condensados, distintos e discretos e 
podem ser representados como números em uma tabela ou matriz contendo 
variáveis não sobrepostas e seus valores. Por outro lado, os dados 
qualitativos não têm uma estrutura de tabela ou lista e  não consistem em 
variáveis não sobrepostas e seus valores. Os dados qualitativos podem ter 
várias estruturas, por exemplo, a estrutura de um texto, com palavras 
formando frases. Os dados qualitativos podem ser codificados, mas esses 
códigos podem se sobre por em termos de posição e/ou significado.  
(Schoonenboom, 2023, p. 18, tradução nossa). 
 A partir de então, as metodologias de coleta e análise se diferenciam 
significativamente entre ambos os tipos. Enquanto para o quantitativo existem 
técnicas robustas como sondagens, questionários e experimentos controlados  
(Rahman, 2016), o qualitativo se apoia em métodos mais flexíveis e exploratórios, tais 
como entrevistas, observações de participantes e análise de conteúdo (Olsen, 2015). 
Essas abordagens distintas refletem as diferentes ênfases na pesquisa, com a 
quantitativa buscando dados mensuráveis para análise estatística, e a qualitativa 
buscando compreensão profunda e contextualizada dos fenômenos em estudo.

2.2 A NATUREZA DE PESQUISAS QUALITATIVAS 
Dada a distinção entre os tipos de pesquisa, tanto na sua natureza básica 
quanto aplicada, quando assumem uma abordagem descritiva, estas se tornam 
empíricas e investigativas (Mattar; Ramos, 2021), proporcionando uma interpretação 
tangível a partir de elementos etnográficos e até mesmo subjetivos coletados (Aspers; 
Corte, 2019). 
Esse tipo de investigação pode ser  então operacionalizado conforme a 
estrutura definida por Américo (2021), onde as estratégias são definidas caráter da 
pesquisa e informam os métodos para a condução do trabalho, conforme apresenta o 
diagrama da Figura 1.

A pesquisa qualitativa, portanto, tem como objetivo compreender os fenômenos 
comportamentais, as emoções e os eventos humanos através de estratégias e 
paradigmas que orientam o pesquisador a adotar abordagens holísticas. Essas 
abordagens demandam métodos específicos para a coleta e anális e de cada tipo de 
informação, possibilitando uma compreensão mais profunda e contextualizada desses 
aspectos.

2.2.1 Estratégias, paradigmas e abordagens 
Ao adentrar nesse campo, compreender as diretrizes que orientam o processo 
de investigação. Estas diretrizes metodológicas não apenas delineiam o caminho a 
seguir, mas também moldam a maneira como os pesquisadores concebem e 
interpretam os fenômenos estudados, também podendo ser chamadas de paradigmas 
de pesquisa: 
O paradigma funcionaria como o mapa ou roteiro de uma ciência, 
fornecendo critérios para delimitar problemas, formular questões, determinar 
o que deve ser observado, coletar dados, analisar resultados e assim por 
diante. Corresponderia, portanto, a um conjunto de práticas que caracterizam 
determinada ciência, incorporando os valores e as crenças dos cientistas da 
área. (Mattar; Ramos, 2021, p. 23). 
Assim, no âmbito qualitativo, os paradigmas mais comuns utilizados para guiar 
os estudos estão relacionados com a fenomenologia (Groenewald, 2004), etnografia 
(Sangasubana, 2014) ou a grounded theory (Corbin; Strauss, 2015). 
A fenomenologia é uma abordagem filosófica e método de pesquisa qualitativa 
que busca compreender os fenômenos humanos a partir da perspectiva dos próprios 
sujeitos envolvidos  (Qutoshi, 2018) . Em pesquisas qualitativas, a fenomenologia 
procura investigar os significados que as pessoas atribuem às suas experiências  
incluindo seus pensamentos, sentimentos e percepções (Bliss, 2016). 
Semelhantemente, a etnografia se concentra na compreensão das práticas 
culturais, valores, crenças e comportamentos de um grupo específico de pessoas em 
seu contexto natural  (Ayar; Yalvac, 2022; Sangasubana, 2014) . Diferentemente da 
fenomenologia, que se concentra nas experiências individuais, a etnografia busca 
compreender as dinâmicas culturais de um grupo social em particular. 
A teoria fundamentada, ou grounded theory, por outro lado traz uma abordagem 
mais indutiva. Este método visa desenvolver teorias explicativas ou interpretativas a 
partir dos dados coletados durante a pesquisa , permitindo que as hipóteses surjam 
organicamente a partir das observações e interações dos participantes  (Glaser; 
Strauss, 2017) . Por seu caráter sistemático, a grounded theory  segue etapas pré -
definidas para chegar a uma teoria, conforme mostra o fluxograma da Figura 2.

O paradigma inicia-se com a coleta de uma ampla gama de dados relevantes 
para o fenômeno estudado. Em seguida, os pesquisadores realizam a codificação dos 
dados, identificando padrões, temas e conceitos emergentes , este processo é 
iterativo, com uma comparação constante entre novos dados e dados existentes, 
refinando categorias e conceitos conforme necessário. 
A partir da análise dos dados codificados, os pesquisadores desenvolvem 
teorias ou modelos explicativos que descrevem e explicam os padrões e processos 
observados, sendo essas teorias fundamentadas nos próprios dados, derivadas 
diretamente das observações feitas durante a pesquisa. Por fim, a saturação teórica 
é atingida quando os pesquisadores consideram que já coletaram dados suficientes e 
que novas informações não estão mais levando a insights significativos ou mudanças 
nas teorias desenvolvidas, indicando que a análise está suficientemente desenvolvida. 
2.2.2 Coleta de dados qualitativos 
Embora os paradigmas se diferenciem entre si , o ponto em comum entre eles 
são as metodologias de coleta de dados, que em todos os casos buscam capturar as 
experiências, perspectivas e significados dos participantes de uma pesquisa  (Flick, 
2018). Ademais, considerando a natureza humana do estudo, é imprescindível adotar 
um rigor ético em todas as fases da pesquisa  (Olsen, 2015). Isso implica seguir as 
normativas estabelecidas por comitês de ética, assegurando a integridade e o bem -
estar dos participantes durante todo o processo de investigação.

Dessa forma, os métodos de coleta são diversos, sendo os mais comuns para 
essas abordagens são: 
Entrevistas: estruturadas, semiestruturadas ou abertas, as entrevistas 
permitem uma exploração detalhada das experiências e opiniões dos participantes. 
Observação Participante: envolve a imersão do pesquisador no ambiente natural

Observa-se que em todos esses cenários, os dados gerados exibem um caráter

textos, áudios ou outros artefatos. Essa heterogeneidade na sua apresentação 
demanda uma abordagem flexível e sensível na análise, considerando a riqueza e 
complexidade das experiências humanas (Américo, 2021). 
2.3 PROCESSAMENTO E ANÁLISE DE DADOS QUALITATIVOS 
Diante a  ampla variedade de informações, é importante adotar abordagens 
meticulosas para extrair delas insights relevantes ou para desenvolver teorias 
robustas e fundamentadas (grounded theory).  
Os dados qualitativos, pela sua própria natureza, frequentemente se 
manifestam, ou são transformados, em forma textual, o que possibilita uma QDA mais 
aprofundada e interpretativa  (Lester; Cho; Lochmiller, 2020) . Assim, para lidar com 
essa complexidade, emprega-se estratégias que permitam estruturar e compreender 
esses dados de maneira eficiente. Uma dessas estratégias é a utilização de técnicas 
de codificação, que permitem uma organização sistemática e uma análise mais 
criteriosa das informações. 
2.3.1 Codificação dos dados 
Sendo a técnica mais comum para o processamento dos dados subjetivos, a 
codificação qualitativa é uma das tarefas mais importantes na pesquisa qualitativa. 
Dessa forma  podendo ser definida como “ um processo sistemático, subjetivo e 

--- page 22 ---
22 
 
transparente de redução de dados a conceitos significativos e confiáveis que 
representam adequadamente os dados e abordam o problema da pesquisa, objetivo 
ou pergunta” (Adu, 2019, p. 23). 
Dessa forma, a codificação consiste na técnica de associar códigos, etiquetas, 
rótulos ou tags à determinados trechos d a informação. Um código pode ser definido 
como “uma palavra ou frase curta que atribui simbolicamente um atributo sumativo, 
saliente, que captura a essência e/ou evocativo para uma parte dos dados” (Saldana, 
2012, p. 3). 
Embora essa abordagem seja uma ferramenta poderosa, também apresenta 
desafios e considerações importantes. É fundamental que os pesquisadores estejam 
conscientes de questões como vieses pessoais, interpretação subjetiva e contexto 
cultural, que podem influenciar o processo de codificação e os resultados obtidos  
(Bytheway, 2018) . Além disso, à medida que o volume de informações cresce, o 
processo de codificação pode se tornar cada vez mais complexo e exigente para o 
pesquisador, demandando um esforço significativo para garantir uma análise 
detalhada e precisa (Mohajan; Mohajan, 2022). 
2.3.1.1 Técnicas e processo de codificação 
Dentro dessa metodologia ainda existem tipos de codificação que podem ser 
aplicadas em conjunto ou isoladamente . Williams; Moser (2019)  definem que ao 
utilizar essa técnica, baseando -se na grounded theory , passa por 3 estágios de 
codificação: aberta, axial e seletiva , conforme mostra o fluxograma da  Figura 3. O 
número de rótulos diminui constantemente ao longo dessas etapas. 
Durante a primeira fase, codificação aberta, busca por dividir os dados 
qualitativos em partes discretas, examinando-os de perto e comparando-os quanto a 
semelhanças e diferenças (Corbin; Strauss, 2015). O pesquisador, portanto, começa 
a atribuir os códigos de acordo com a sua percepção. Posteriormente esses códigos 
serão agrupados e refinados de forma iterativa, conforme novos dados ou insights são 
descobertos e os estágios da codificação avançam. 

--- page 23 ---
23 
 
Fonte: adaptado de (Williams; Moser, 2019, p. 47) 
Na fase subsequente da análise, conhecida como codificação axial, o 
pesquisador realiza uma refinada análise dos códigos previamente atribuídos durante 
a codificação aberta. Nesse estágio, o foco recai sobre a identificação das relações e 
conexões entre os códigos, buscando compreender como os diferentes elementos se 
interrelacionam e se agrupam em categorias mais amplas (Mohajan; Mohajan, 2022). 
O pesquisador examina de forma sistemática as associações entre os códigos, 
explorando as complexidades e padrões subjacentes aos dados. 
No estágio final, codificação seletiva, o esforço concentra -se na seleção dos 
códigos mais significativos e relevantes para a investigação  (Williams; Moser, 2019). 
Aqui, os códigos previamente identificados durante a codificação aberta e axial são 
cuidadosamente revisados e avaliados à luz dos objetivos da pesquisa e dos 
principais temas emergentes  (Skjott Linneberg; Korsgaard, 2019) . O pesquisador 
busca identificar os códigos que melhor representam os padrões e tendências mais 
proeminentes nos dados, priorizando aqueles que oferecem insights mais profundos 
e contribuem para uma compreensão abrangente do fenômeno em estudo  (Saldana, 
2012).

realizadas sobre os dados é crucial para assegurar a confiabilidade e a solidez da 
pesquisa (Skjott Linneberg; Korsgaard, 2019) , através da transparência e 
comunicação adequada dos processos (Lester; Cho; Lochmiller, 2020). 
Tendo em base os resultados da codificação, os dados agora estão mais

3 METODOLOGIA 
Dadas as características e desafios inerentes à pesquisa qualitativa, bem como 
das técnicas de codificação que sustentam as suas análises, é necessário delinear a 
metodologia que guiará o desenvolvimento de um software que atenda aos requisitos 
desse campo.  
A seção que segue descreve a metodologia aplicada no desenvolvimento do 
software, desde a concepção da sua arquitetura até a avaliação. Esse processo 
metodológico será estruturado para garantir que o software não apenas reflita os 
princípios discutidos na seção anterior, mas também ofereça uma solução prática  e 
adaptável às demandas reais de análise qualitativa. 
3.1 CICLO DE VIDA DE UM SOFTWARE 
O desenvolvimento de software, no presente contexto de uma aplicação voltada 
para a análise qualitativa de dados, exige um planejamento cuidadoso e estruturado. 
O ciclo de vida de um software – do inglês, Software Development Life Cycle (SDLC), 
é uma metodologia que descreve as etapas envolvidas desde a concepção inicial do 
projeto até a sua finalização e manutenção  (Royce, 1987) . Essa abordagem 
sistemática garante que a aplicação seja desenvolvida de forma eficiente, atendendo 
aos requisitos de qualidade e funcionalidades esperados. 
O SDLC pode ser dividido em várias etapas, cada uma com suas atividades 
específicas, objetivos e entregáveis. Entre os modelos mais conhecidos estão o 
modelo em cascata ( Waterfall), o modelo incremental, o modelo espiral, e as 
metodologias ágeis (Agile) (Sommerville, 2019). 
Neste projeto, adotou -se uma abordagem iterativa (Larman; Basili, 2003) . A 
implementação dessa metodologia favorece o refinamento constante, com foco na 
entrega incremental de valor, seguindo um ciclo contínuo de avaliação e ajustes .

Com o passar do tempo, eles aprimoram as versões iterativamente até que o 
software completo esteja pronto para produção. A equipe pro duz uma nova 
versão do software ao final de cada iteração (AWS, 2024).

como "tutoriais", "entender" e "passo" (possivelmente relacionado à expressão "passo 
a passo"). Esses termos indicam a necessidade de um manual de uso mais detalhado, 
com mais tutoria is e exemplos práticos sobre a utilização do software, desde a 
instalação até o uso de suas funcionalidades. 
Em relação à "funcionalidade", os usuários destacaram termos como 
"visualização" e "processo". O termo "visualização" refere -se à forma como as 
informações são apresentadas aos usuários, sugerindo que a interface poderia exibir 
os dados de maneira mais clara ao longo do processo de codificação. Por exemplo, a 
funcionalidade de "visualizar o conteúdo de cada código" foi apontada como uma 
melhoria necessária, conforme  é citado no exemplo  do capítulo  5.2. Já o termo 
"processo" relaciona-se à demanda por funcio nalidades que tornem o processo de 
codificação mais ágil, como a sugestão automática de rótulos baseada em algoritmos 
de aprendizado de máquina. No entanto, essa funcionalidade ficou fora do escopo da 
versão atual devido à sua complexidade. 
Por fim, embora o design da interface não tenha sido o foco principal desta 

--- page 67 ---
67 
 
versão do software, algumas respostas apontaram para a necessidade de revisões no 
"layout". Termos como "interface" e "tela" sugerem a necessidade de maior fluidez na 
operação, enquanto "responsividade" destaca as limitações da biblioteca utilizada 
para o desenvolvimento da interface gráfica (Tkinter), que carece de suporte robusto 
para recursos como a responsividade. 
A partir dessas observações, é possível responder à última questão da 
investigação: "Quais aspectos da interface e das funcionalidades precisam ser 
aprimorados?" – Os principais pontos de melhoria incluem a necessidade de uma 
visualização mais clara durante o processo de codificação e a inclusão de 
funcionalidades, como a sugestão automática de rótulos. No que diz respeito à 
interface, é essencial aprimorar a fluidez e a responsividade, superando as limitações 
da biblioteca Tkinter. Graças à arquitetura em três camadas adotada no 
desenvolvimento, há flexibilidade para até mesmo mudar a linguagem da interface, 
garantindo que essa possibilidade de melhoria seja feita sem um esforço geral. 
Dessa forma, identificam -se os requisitos que poderão ser incorporados nas 
próximas iterações do Ciclo de Vida de Desenvolvimento de Software (SDLC) do 
nosso projeto. Entre os requisitos futuros, destacam-se: 
a) Melhor visualização dos códigos e trechos de dados; 
b) Sugestão automática de rótulos com aprendizado de máquina; 
c) Manual de uso mais detalhado, com tutoriais práticos; 
d) Substituição da biblioteca Tkinter  por uma interface mais moderna e 
responsiva; 
e) Integração com outras ferramentas de análise qualitativa. 
6.3 LIMITAÇÕES 
Diante dos resultados e análises apresentados, reconhece -se que o software 
ainda não atingiu o grau de maturidade necessário para uma distribuição em larga 
escala. Contudo, essa possibilidade já havia sido prevista desde a concepção do 
projeto. A escolha de um SDLC iterativo permite justamente a revisão e 
aprimoramento contínuo dos requisitos, permitindo que cada iteração traga melhorias 
significativas ao software. 
A seleção dos requisitos a serem trabalhados em cada iteração depende 

--- page 68 ---
68 
 
diretamente de fatores como o tamanho da equipe, a disponibilidade de recursos e o 
tempo dedicado ao projeto — aspectos que, neste trabalho, foram limitados. Essas 
restrições influenciaram diretamente o ritmo de desenvolvimento e o alcance das 
funcionalidades implementadas na versão inicial. 
Apesar desses desafios, o software apresentou notas medianas  nas 
avaliações, o que indica que, embora longe da excelência, ele cumpre os requisitos 
básicos estabelecidos no planejamento. A pontuação moderada nas escalas de 
usabilidade e satisfação sugere que o sistema atende, de forma funcional, às 
necessidades dos usuários, mas ainda precisa de melhorias significativas. 
Essas limitações podem ser gradualmente mitigadas conforme o software 
passa por novas iterações do ciclo de desenvolvimento. À medida que mais recursos 
sejam alocados e mais feedback dos usuários seja coletado, o sistema poderá evoluir, 
ganhando robustez e refinamento necessários para alcançar um nível de maturidade 
adequado para uma adoção mais ampla.

7 CONSIDERAÇÕES FINAIS 
Com o aumento exponencial no volume de dados gerado s, a análise de 
informações qualitativas se torna cada vez mais comum para diversas áreas do 
conhecimento. Esses dados, por sua natureza não estruturada e subjetiva, requerem 
técnicas específicas que possam extrair insights significativos. Dentre essas técnicas, 
a codificação se destaca como uma abordagem central, permitindo que padrões e 
conceitos emergentes sejam identificados e organizados de maneira sistemática. Para 
apoiar esse processo, os softwares de análise assistida por computador, conhecidos 
como CAQDAS, desempenham um papel fundamental, agilizando e estruturando o 
trabalho dos pesquisadores. 
Este trabalho focou, portanto, no desenvolvimento de um software dedicado à 
codificação de dados qualitativos, buscando preencher lacunas importantes 
observadas no mercado atual de CAQDAS, como o alto custo das ferramentas 
comerciais e a escassez de soluções robustas em código aberto. O objetivo principal 
foi criar uma alternativa acessível e eficiente, que democratizasse o uso dessas 
ferramentas, permitindo que mais pesquisadores tivessem acesso a uma plataforma 
de codificação de dados sem os altos custos das soluções proprietárias. 
A metodologia de desenvolvimento adotada seguiu o modelo de SDLC iterativo, 
em que as fases de análise, design, implementação e testes são continuamente 
repetidas, permitindo melhorias graduais e sucessivas ao longo do ciclo de vida do 
software. Esse proce sso iterativo garantiu a flexibilidade necessária para incorporar 
feedbacks e realizar ajustes progressivos à medida que o software evolui. A 
arquitetura, por sua vez, foi a de três camadas, separando a interface do usuário, a 
lógica de negócios e o armazenamento de dados. Essa escolha técnica proporcionou 
independência entre os componentes do sistema, favorecendo a modularidade, 
manutenção e futuras expansões, além de facilitar ajustes sem a necessidade de 
reestruturar toda a aplicação. 
Dessa forma, a avaliação da primeira versão do software revelou que, apesar 
de atender aos requisitos iniciais de funcionalidade, a taxa de aceitabilidade entre os 
usuários ficou em um nível neutro. Esse resultado reflete que, embora o software 
tenha potencial, ele aind a não está totalmente pronto para ser amplamente utilizado 

--- page 70 ---
70 
 
ou divulgado para o público geral. Melhorias significativas são necessárias, 
especialmente no que diz respeito a funcionalidades mais robustas  e à interface 
gráfica, que foram identificadas como pontos críticos a serem aperfeiçoados. Contudo, 
essas melhorias podem ser implementadas de forma eficiente, uma vez que a 
separação em camadas permite a reformulação da interface sem comprometer a 
lógica de negócios ou o armazenamento de dados. 
Além disso, a análise do feedback dos usuários destacou que o software atende 
apenas parcialmente ao seu objetivo principal: ser uma ferramenta acessível que 
facilite o processo de codificação de dados qualitativos. Para cumprir integralmente 
as expectativas do público -alvo, algumas necessidades devem ser atendidas, 
conforme os pontos acima mencionados. 
Apesar dessas limitações, o projeto já alcançou um avanço importante ao 
oferecer uma alternativa viável e de baixo custo para a análise qualitativa. No entanto, 
ainda há um longo caminho a ser percorrido até que o software se estabeleça como 
uma solução completa no mercado de CAQDAS. 
Por fim, o presente trabalho deixa claras as oportunidades para futuras 
iterações de desenvolvimento. Através de um modelo colaborativo, o software foi 
disponibilizado em um repositório público, incentivando a participação da comunidade 
científica e de des envolvedores. As próximas etapas incluem a implementação de 
novos requisitos, como os mencionados no capítulo 6, e o aperfeiçoamento contínuo 
do sistema com base no feedback dos usuários. A expectativa é que, com o tempo e 
contribuições da comunidade, o software possa evoluir para se tornar uma ferramenta 
de referência para a análise qualitativa, atendendo tanto às demandas  de cada 
público.
